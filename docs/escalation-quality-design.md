# Escalation quality and policy adaptation screening

This experiment asks whether escalation improves a real compiler choice and whether its policy can adapt with less maintained logic. It extends the working harness compiler without changing LLVM's retained allocation policy. The machine-readable [frozen design](../experiments/escalation-quality-v1.json) is committed before outcomes are collected.

Six generated kernel families are split by family: polynomial and rotate/xor for fitting; cross-lane and dot-product for routing calibration; masked recurrence and alternating inputs for untouched evaluation. Each has 24- and 32-lane variants. Two observation sites per variant are chosen at the 25th and 75th percentiles of ambiguous first-policy states, by ordinal position rather than outcome. The resulting 24 observations remain clustered within six synthetic families; they are not 24 independent real-world workloads.

At each site, query Jev and Codex once on the identical packet. Replay the exact prefix and verify the state fingerprint before changing one action. After the intervention, use a fresh first-eligible continuation. Compile each distinct proposed action from first, last, seeded uniform, minimum use/definition density, Jev, Codex and a fitted nearest-neighbour selector. Models receive the same compiler features as the cheap scorer. Stock LLVM remains a separate end-to-end reference. Best measured action means the best in this restricted candidate pool, not a global optimum.

The nearest-neighbour scorer uses candidate features, never raw register-column identities across states. Feature ranges, distance, tie-breaking and exemplars are fitted on fitting-family outcomes only. Routing chooses a confidence threshold on the separate calibration families; the fixed grid includes never and always escalate. The objective is measured log runtime with a 2% tie floor and at most 25% escalation on calibration. A threshold does not guarantee the same rate on new data; test overruns count against success. Jev confidence remains a distribution-derived score, not correctness probability.

All candidates must pass independent native references and checksum agreement. Timing excludes reference checks and measures the affected kernel separately. Use eleven seeded interleaved rounds, targeting approximately 100 ms per executable sample with a common per-case iteration count chosen from stock. Identical generated instruction sections share samples. Report paired log-runtime ratios, family aggregates, wins/losses and measured timing variability. Gains below the larger of 2% and observed paired variability are inconclusive. Two test families cannot justify broad statistical generalization.

The workload shift doubles loop rounds and raises live values to 40 then 48. Evaluate frozen policies first. Allow both the cheap scorer and routing threshold to use identical 40-lane outcome labels, then evaluate their adapted versions at 48 lanes. Prompts and feature definitions stay fixed. Record additional exemplars, labels, threshold/configuration changes and provider calls. This is a controlled pressure-extrapolation exercise; parameter count, prompt size or zero edits alone do not prove reduced long-term maintenance.

Success requires correct outputs, a cascade improvement over Jev beyond noise in a consistent direction across both held-out families, test escalation no more than 25%, and competitiveness with the cheap learned selector. Beating stock is a separate requirement for practical compiler benefit. Never-escalate calibration, unchanged actions or code, noise-sized differences, or a cheap selector matching the cascade fail to establish escalation value. No forced escalation or post-test prompt tuning is allowed.

The current model adapters, compiler source, corpus generator, orchestration, prompts and policy implementation are hashed into the run evidence. Authentication is inherited from the working pilot. There is no token cap; usage and latency are recorded. No hardware rental, GPU or production change is involved.
