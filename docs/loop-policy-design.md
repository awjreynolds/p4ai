# Loop-local policy experiment

The previous single-eviction experiment found little useful variation in generated code. This screening moves to one larger compiler decision: the vectorization factor (VF) and interleave count (IC) for an identified loop, on the local Apple M3 Max CPU. The initial design was recorded in commit `8a9fed8`; independent review tightened the success gates before any timings or model calls, requiring improvement over the cheap learned control and a held-out escalation rate at most 25%.

The decision contract selects from eight loop-local directives: stock LLVM, VF1/IC1, VF2/IC1, VF4/IC1, VF8/IC1, VF4/IC2, VF4/IC4, and VF8/IC2. LLVM still checks legality and performs downstream optimizations. A directive may be ignored or clamped; the build evidence records requested and realized values, compiler remarks, optimized IR, and object code identity. Identical code shares timing observations. Ordinary unrolling is not an experimental action.

This is selection among loop-local VF/IC directives, with LLVM legality and downstream optimization retained. It does not replace the whole vectorizer cost model or introduce a new internal callback. At the pinned LLVM revision, `LoopVectorize.cpp` takes user VF/IC hints into planning, returns the requested VF plan when valid, and overrides IC when safe. See `llvm/lib/Transforms/Vectorize/LoopVectorize.cpp` around `processLoop` and `computeBestVF`, and `LoopVectorizationPlanner.cpp` for realized-width remarks. These files are available in the pinned source checkout produced by the bootstrap.

## Controls and discovery gate

The mechanical selector returns one fixed action. Fit that action on discovery measurements, allowing stock LLVM to win. This avoids making the simple baseline deliberately weak. A one-nearest-neighbor candidate-loss predictor is the additional cheap learned control. It uses discovery labels and training-only feature scaling; it does not acquire hand-written family-specific rules.

Discovery uses affine, reduction and 64-bit hash loops. Routing calibration uses dot product and conditional loops. Final evaluation uses polynomial, strided-access and stencil loops. Each family has fixed trip counts 257, 1027 and 4099, including tails. These synthetic families constitute a screening corpus, not independent production applications. Every kernel is linked to a separate scalar-reference driver, tested natively, and compiled for explicit `apple-m3` CPU and tuning settings.

On the first discovery timing block, select both the best fixed action and each case's best candidate. Confirm those frozen choices on a second interleaved block. The confirmed family-balanced runtime reduction must reach 5%, exceed the noise bound, and be positive in at least two discovery families. At least half the discovery cases must have distinct code outcomes. A failed gate stops all provider calls for this design. Changing boundaries requires a new design and preserved negative evidence.

The complete thresholds and partitions are in [the frozen machine-readable design](../experiments/loop-policy-v1.json). Each block has 11 rounds of approximately 100 ms per stock sample, with shuffled execution order. Iterations are shared across arms and cached across blocks. The descriptive noise bound is the larger of 2% and three times the maximum within-case paired log-ratio MAD. It is not a confidence interval or a proof of statistical significance.

## Model evaluation

Only after discovery passes, Jev and Codex each select one directive for every calibration and held-out packet. Packets contain numerical source features, the action menu and fixed target facts. They exclude family names, case paths and observed timing outcomes. Successful responses are cached separately, invalid attempts retained, and identical packets reused. Model work and builds occur outside timing blocks.

Fit the routing threshold only on calibration outcomes, with a 25% calibration escalation ceiling and `never` as an eligible result. Freeze it before final evaluation. Report the actual held-out rate, including any budget overrun. Compare the cascade with the fitted constant, Jev alone, Codex alone, the cheap learned selector and stock LLVM. Model calls on all packets are an offline measurement cost; they are distinct from calls a deployed cascade would make.

A useful escalation result needs held-out gains beyond the declared noise bound, positive direction in at least two of three held-out families, and improvement beyond the same bound against the cheap learned control. Both calibration and held-out escalation rates must be at most 25%. Nine held-out cases permit two escalations, making the required two-family improvement possible. This third trip count was added before measurement after review caught the arithmetic incompatibility in the original six-case design. Neither a provider disagreement nor a different binary establishes better decisions. Count policy rules, fitted constants, learned exemplars, routing parameters, features and prompt content. This experiment cannot establish reduced human maintenance effort or long-term adaptation costs.
