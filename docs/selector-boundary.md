# LLVM register-allocation action boundary

This spike targets LLVM revision `32d702efa29d0fdd02cff7b79dea8fdbbcf059d4`, in `llvm/lib/CodeGen/MLRegAllocEvictAdvisor.cpp`, at `MLEvictAdvisor::tryFindEvictionCandidate`. The C++ patch itself replaces no register-allocation policy; the Python harness uses this existing interface to replace the eviction choice. The patch adds a runtime guard around the action returned by the ML eviction advisor, before that action is used as an index into `Regs`.

This is an existing MLGO integration boundary: release and development advisors already use LLVM's model-runner interface, including the interactive runner exercised by `llvm/test/CodeGen/MLRegalloc/interactive-mode.ll`. The patch makes that discrete action contract fail closed. It does not claim that NVPTX uses this register-allocation advisor or change NVIDIA scheduling.

The advisor returns a signed `int64_t` position. Physical-register candidates are generated in `AllocationOrder` order, limited by `getOrderLimit`, and admitted only when `canAllocatePhysReg` accepts them. `loadInterferenceFeatures` supplies the per-position mask after checking physical interference, fixed registers, completed live ranges, interference-query limits, eviction-count caps, cascade age, and urgent cases. The last model column, `CandidateVirtRegPos`, represents the live range seeking allocation; it is available only when an eviction is not mandatory. The model chooses among these indexed candidates. It never supplies a physical-register ID.

The guard rejects negative positions before conversion to `size_t`, positions outside the model columns, physical positions outside the visited allocation order, and any action whose mask is zero. The final virtual-register column remains valid when its mask is one and still means “do not evict.” Invalid actions stop compilation with `reportFatalUsageError`; they are not clamped, remapped, retried through another advisor, or silently repaired.

The boundary retains LLVM's surrounding decisions: `getOrderLimit`, `canAllocatePhysReg`, allocation-order hints, candidate feature construction and masks, `DefaultEvictionAdvisor` handling for hint interference and fallback, cascade and repeat-eviction limits, and RAGreedy's subsequent allocation, splitting, and spilling. The change only enforces the existing action contract at runtime in assertion-disabled builds as well as assertion-enabled builds.

The source pin and existing MLGO interactive runner provide a reproducible compiler-backed check. The pinned build is configured Release with assertions enabled, with AArch64 and BPF targets. Run the compiler build and the focused `MLRegalloc` lit test after the guard lands. A negative reply must produce the corresponding `LLVM ERROR: Regalloc: ML eviction advisor ...` message before indexing; legal masked candidates and the enabled virtual-register column must remain accepted. This establishes fail-closed action handling only. It says nothing about allocation quality, compile-time or runtime performance, and it does not depend on or claim NVIDIA GPU access.
