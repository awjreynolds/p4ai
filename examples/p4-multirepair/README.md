# Structurally varied P4 discovery inputs

These synthetic programs reuse the earlier TNA parser/deparser scaffolding, but generate different dependency and control graphs: repeated fork/join diamonds, mutually exclusive service chains, and chains with accumulating multi-output actions. Optional independent tenant-policy lookups compete with those critical paths for placement; with these enabled group a is the independent tables and group b is the primary graph. They are not independent real-world applications.

Run `python3 examples/p4-multirepair/selfcheck.py` for static generation checks. Generate fresh inputs with `python3 examples/p4-multirepair/generate.py --spec SPEC.json --output NEW_DIRECTORY`. A spec names `structure`, `rounds`, `entries`, `key_bits`, and optionally `join_entries`, `outputs`, `parameter_bits`, `extras` or `extra_entries`. Each table retains its required capacity in every candidate. Four fixed-width annotation slots and the same `program.p4` basename control source-position changes. All 26 policies are uniform across cases; the generator labels none as a repair.

Discovery uses the existing pinned Tofino compiler/probe. Every attempt stays in its own directory; no source or result is overwritten. Initial development exploration is capped at approximately 40 compiler probes before review, not a model-token budget. Candidate policies are alternatives applied to default, never accumulated. Qualification requires a genuine default resource rejection and an annotation-only compiler/assembler fit with capacities and application interface preserved. Static source checks do not prove packet execution.

Development evidence may inform every selector equally. Test curation is separate under `artifacts/p4-multirepair-curation/sealed/`; identities, parameters and results remain unavailable to selector designers until their policies are frozen. Selection aims for multiple structures and repair mechanisms, plus baseline-fitting and no-known-repair controls. All search attempts and exclusions remain evidence, including failed exploration. Cases are selected before any adviser runs; no case is chosen to favor a measured selector result. Failure to qualify the requested diversity is a corpus limitation, not a reason to fabricate labels.
